# Round 3: two teammates (November 10, 2026)

Mnemolith 0.4 before release (the `team-memory` branch), Claude Code with its default model, one run per task and
setup. Batches 20261110-131906 (tasks 1–4), 20261110-181857 (tasks 5–7, final scoring) and 20261110-180449 (tasks 5–7,
first scoring).

## What it tests

Two clones of the same repo, teammate A and teammate B, each with their own personal memories.

1. **Session 1, in A's clone.** A tells their AI something about the project and adds "Make sure the rest of the
   team's AI tools know this too."
2. A commits and pushes whatever that session left in the repo. In three tasks, another teammate then commits a
   change that makes what A shared no longer true.
3. **Session 2, in B's clone, fresh.** B's AI gets a task that needs what A said.

Four setups:

| Setup | What A's AI has to share with |
| --- | --- |
| No memory | nothing |
| CLAUDE.md notes | a notes file in the repo, which already holds the team's everyday facts |
| Mnemolith, personal only | its own memories, which never reach B (what 0.3.5 does) |
| Mnemolith, team memory | the repo's team memory, which already holds the same everyday facts |

## Results

**Tasks 1–4: B needs what A shared.**

| Task | No memory | CLAUDE.md notes | Personal only | Team memory |
| --- | --- | --- | --- | --- |
| staging-db: use the staging database A mentioned | 0/1 | 0/1 | 0/1 | **1/1** |
| pricing-changelog: log pricing changes where finance reads them | 1/1 | 1/1 | 1/1 | 1/1 |
| api-frozen: don't change the API a partner depends on | 1/1 | 1/1 | 1/1 | 1/1 |
| refund-approval: big refunds need a manager | 0/1 | 1/1 | 0/1 | **1/1** |
| **Total** | 2/4 | 3/4 | 2/4 | **4/4** |

**Tasks 5–7: the code changed after A shared.** A pass is either doing what the code now needs, or leaving the code
alone and telling the user the shared rule looks out of date. Following the old rule without noticing fails.

| Task | No memory | CLAUDE.md notes | Personal only | Team memory |
| --- | --- | --- | --- | --- |
| api-unfrozen | 1/1 | 1/1 | 1/1 | 1/1 |
| payments-ours | 1/1 | 1/1 | 1/1 | 1/1 |
| pricing-log-moved | 1/1 | 1/1 | 1/1 | 1/1 |

**Cost** (B's session, API prices): team memory about $0.15 per task, CLAUDE.md $0.12–0.14, personal only about
$0.14, no memory about $0.13.

## What we learned

- **Team memory does its job.** What A told their AI reached B's AI in every run. With personal memory only, it
  never does, which is the gap team memory was built to close.
- **It's close to a shared notes file on accuracy.** The one difference is staging-db. That matches round 2, where
  CLAUDE.md missed the staging database in all three runs: across rounds 2 and 3, a fact mentioned in conversation
  ("no code changes for now") didn't reach the next session through the notes file in any of 4 runs, and did
  through Mnemolith in all 4. One run per task here is too few to claim more than that.
- **The outdated flag didn't change outcomes in this repo.** With realistic commit messages, every setup either
  handled the new code or noticed the change. Claude reads code carefully, and in a small repo it sees the change
  whatever its notes say. Round 1 found the same. The flag should matter more in large repos, where nobody reads
  every file, but this evaluation doesn't show that.
- **Team memory costs a little more**, about 10–20% per task over a notes file in these runs. Worth looking into
  before release.

## What we fixed along the way

- **Sharing didn't link the files a fact names.** A's AI shared "API v1 (shop/api/v1.py) is frozen" without passing
  `files=`, so it could never be flagged as outdated. Mnemolith now links files named in a shared memory's text
  itself, and the share tool asks for `files=` every time.
- **Claude didn't know the repo had a team memory** without searching for the tool. When you use a repo's team
  memory, Mnemolith's instructions now say so.

## How the evaluation changed, so nothing is hidden

- **First attempt at tasks 5–7: the commits gave the answer away.** Their messages announced the new rule ("v1 is no
  longer frozen"), so B's AI ignored the old one in every setup. The commits now describe the change the way real
  ones do ("Add id to API v1 product"), and the code still shows it.
- **Second attempt: the scoring was too strict.** It only accepted changing the code. In payments-ours, B's AI with
  team memory saw the "possibly outdated" flag, found the function the memory pointed to was gone, and stopped to tell
  the user instead of editing another team's code. That's what you'd want from a teammate, so stopping and saying the
  rule looks out of date now counts as a pass, in every setup. Under the stricter scoring (batch 20261110-180449),
  no memory and personal only passed 3/3, and CLAUDE.md and team memory 1/3.
- All results above use the final tasks and scoring, except tasks 1–4, which didn't change.

Run it yourself: `cd eval && python3 run.py --suite v3`, then `python3 report.py`.
